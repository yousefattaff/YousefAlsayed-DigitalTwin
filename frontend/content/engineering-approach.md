# What has shaped your engineering approach? (en)

My background in Embedded C, microcontrollers, and autonomous robots taught me to care about systems working in practice. My current work combines Python engineering, AI workflows, retrieval, tool integration, testing, and model evaluation.

# What is an example of solving a concrete engineering problem? (en)

At Arche Robotics, I replaced 30-minute polling with DynamoDB Stream triggers for approximately 0.3-second log capture. I also fixed an MCP nested-payload parsing bug and added battery and telemetry recovery watchdogs. These changes addressed specific problems in a robot-monitoring workflow.

# How do you handle missing information or failed actions in your projects? (en)

RAG-AI-Agent cites the source file and page, and skips the model when the uploaded files do not contain the answer. SDR Multi-Agent reports a failed email send as a failure. These project behaviors make the available evidence and the result of an action visible to the user.

# إيه اللي أثّر في طريقتك في الهندسة؟ (ar)

خلفيتي في Embedded C والـ microcontrollers والروبوتات المستقلة علّمتني أهتم إن الأنظمة تشتغل عمليًا. شغلي الحالي بيجمع Python و AI workflows والاسترجاع وربط الأدوات والاختبارات وتقييم الموديلات.

# إيه مثال لمشكلة هندسية حلّيتها؟ (ar)

في Arche Robotics استبدلت polling كل 30 دقيقة بـ DynamoDB Stream triggers، بزمن التقاط حوالي 0.3 ثانية. وحلّيت مشكلة تحليل MCP nested payloads وأضفت watchdogs للبطارية والـ telemetry. التغييرات دي عالجت مشاكل محددة في مراقبة الروبوتات.

# مشاريعك بتتعامل مع نقص المعلومات وفشل العمليات إزاي؟ (ar)

RAG-AI-Agent بيعرض اسم الملف ورقم الصفحة وبيتخطى استدعاء الموديل لو الإجابة مش موجودة في الملفات. و SDR Multi-Agent بيعرض فشل إرسال الإيميل كفشل. السلوك ده بيوضح للمستخدم مصدر المعلومات ونتيجة العملية.
